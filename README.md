# ATmega128 ROM Reader

NewTC **AB-M128Pro-A** 베이스보드 위에 **AM-128RAM** CPU 모듈을 꽂은 보드로 HART 메인보드의 ROM/PROM을 읽는 리더입니다. RTOS 없이 동작하는 단일 루프 펌웨어(`RomReader/`)와 PC 덤프 스크립트(`tools/romdump.py`)로 구성됩니다. MCU는 ATmega128, 클럭은 모듈 크리스탈 **16 MHz**입니다.

이전 FreeRTOS 펌웨어는 git 기록(커밋 `1a81ec1`)에 남아 있습니다.

**관련 프로젝트**: [mildstorm/HART](https://github.com/mildstorm/HART) (정원 HART 애플 II 호환기 보드 분석). 덤프할 칩 목록·순서는 HART [`docs/11-rom-dump-list.md`](https://github.com/mildstorm/HART/blob/main/docs/11-rom-dump-list.md)를 따르고, 이 저장소 `rom/HART/`의 덤프는 같은 파일명으로 HART [`rom/`](https://github.com/mildstorm/HART/tree/main/rom)에 복사해 분석합니다 (SHA-1은 HART docs/11 "결과 기록" 표에도 적음).

읽기 전용입니다. 펌웨어에는 쓰기, 소거, 프로그램 펄스가 없고 어떤 핀도 5 V를 넘지 않습니다.

## 1. 대상 칩

목록은 [HART docs/11-rom-dump-list.md](https://github.com/mildstorm/HART/blob/main/docs/11-rom-dump-list.md)를 따릅니다.

| 종류 | 용량 | 핀 | 대상 | `-t` |
| --- | --- | --- | --- | --- |
| 2764 EPROM | 8 KB (8192 × 8) | 28 | U45 C/D8, U46 EF5, U65 VD5, U70 CHR P4 | `2764` |
| 82S129 바이폴라 PROM | 256 × 4 | 16 | U50 1, U51 2, U36 3, U38, U18 M, U17 | `129` |
| 82S123 바이폴라 PROM | 32 × 8 | 16 | U5 | `123` |
| 2732 EPROM | 4 KB | 24 | 고도 F, Malum D0·E0·F0 | `2732` |
| 2716 EPROM (MB8516 포함) | 2 KB | 24 | 고도 KEY, Malum KEY | `2716` |

- 82S129 파일은 256바이트이며 상위 4비트는 0입니다. 오픈 컬렉터인 82S126도 같은 결선과 `-t 129`로 읽힙니다. 데이터 핀에 내부 풀업이 걸려 있습니다.
- U17은 N82S129N입니다(비스듬한 조명에서 표기 판독, 보드 도통으로 82S129 핀 배치 확인).
- 2732·2716은 2764 펌웨어와 2764 결선으로 읽습니다(2.6절).

## 2. 결선

### 2.1 베이스보드 포트 헤더

AM-128RAM 모듈을 꽂은 상태의 베이스보드 10핀 박스 헤더를 씁니다. 매뉴얼(`doc/AB-M128Pro-A/AB-M128PRO-A_manual.pdf` 2.2절) 기준으로 각 헤더는 1–8번이 Px0–Px7(홀수 줄 0, 2, 4, 6 / 짝수 줄 1, 3, 5, 7), **9번이 VCC(5 V), 10번이 GND**입니다. 처음 연결하기 전에 멀티미터로 9번 5 V, 10번 GND를 확인하세요.

헤더 위치(결합 사진 `photo/` 기준, 7805가 왼쪽 위, 7세그먼트가 아래인 방향):

| 헤더 | 위치 | 1번 핀 | 9번(5 V), 10번(GND) |
| --- | --- | --- | --- |
| J117 PORTB | 위쪽 가로, PORTD 오른쪽 | 오른쪽 끝, 보드 위쪽 가장자리 줄 | 왼쪽 끝 |
| J121 PORTC | 왼쪽 세로, UART1 아래 | 아래쪽 끝, 모듈 쪽 줄 | 위쪽 끝 |
| J104 PORTF | 7세그먼트 위 가로, PORTA 오른쪽 | 오른쪽 끝, 모듈 쪽 줄 | 왼쪽 끝 |
| J120 PORTA | 7세그먼트 위 가로, PORTF 왼쪽 | (사용 안 함) | |

1번 핀 위치는 뒷면 사진의 사각 패드와 실크 번호에서 읽은 것입니다. 연결 전에 멀티미터로 9번 5 V, 10번 GND를 꼭 확인하세요. PORTA와 PORTF는 나란히 있어 헷갈리기 쉬우니 실크(PORTA J120, PORTF J104)도 확인하세요.

모듈과 베이스가 결합된 상태에서 각 포트에 걸린 부품(두 회로도와 매뉴얼 3.2, 3.3절 기준):

| 포트 | 모듈(AM-128RAM) | 베이스(AB-M128Pro-A) | 이 리더에서 |
| --- | --- | --- | --- |
| PORTA | SRAM 데이터, 74LVC573, PA0 녹색 LED | 7세그먼트 세그먼트 A–DP | 사용 안 함, Low 고정 |
| PORTB | 없음(PB1 = ISP SCK) | 없음 | A0–A7 |
| PORTC | SRAM A8–A14, PC7 = SRAM /CS | PC0–PC3 7세그먼트 자리 선택 | A8–A12, /CE, /OE. PC7 High 고정 |
| PORTD | 없음 | PD0/PD1 DS1307(I²C), PD2/PD3 UART1 | UART1만 사용 |
| PORTE | PE0/PE1 MAX3232 | 없음 | 사용 안 함 |
| PORTF | 없음 | PF4–PF7 JTAG 헤더 | D0–D7 |
| PORTG | PG0/PG1 SRAM /WE /OE, PG2 ALE | PG0/PG1 LED, PG2/PG3 스위치 | PG0/PG1 상태 LED |

| 헤더 | 포트 | 용도 |
| --- | --- | --- |
| J117 | PORTB | PB0–PB7 → A0–A7 |
| J121 | PORTC | PC0–PC4 → A8–A12, PC5 → /CE, PC6 → /OE, **PC7(8번)은 연결 안 함** |
| J104 | PORTF | PF0–PF7 ← D0–D7 |
| J120 | PORTA | 사용 안 함 |

이유:

- PORTA는 모듈 SRAM 버스(74LVC573, IS62C256), 모듈 녹색 LED(PA0), 7세그먼트 세그먼트가 걸려 있어 데이터 입력으로 쓰지 않습니다. 펌웨어는 PORTA를 Low로 두어 7세그먼트를 끕니다.
- PC7은 모듈 SRAM의 /CS입니다. 펌웨어가 High로 고정해 SRAM이 버스를 잡지 않게 합니다. PC0–PC6에 걸린 SRAM 주소 입력과 7세그먼트 자리 선택은 부하가 아닙니다.
- PORTF의 PF4–PF7은 JTAG 핀입니다. 펌웨어가 기동 시 `JTD`로 JTAG를 끄므로 퓨즈를 바꿀 필요는 없습니다. JTAG 헤더(J115)에는 아무것도 꽂지 않습니다.
- PORTD(UART1, I²C RTC), PORTE(MAX3232가 PE0을 구동), PORTG(LED, 버튼)는 피했습니다.
- PB1은 ISP SCK와 같은 핀입니다. 그래서 덤프할 때는 ISP 케이블을 모듈 J4에서 뺍니다(2.9절). 플래시는 ZIF를 비운 상태에서 합니다. ATmega128의 ISP MOSI/MISO는 PE0/PE1(PDI/PDO)이라 리더 결선과 겹치지 않습니다.

ROM의 VCC와 GND는 같은 헤더의 9, 10번에서 가져옵니다. 2764는 최대 약 100 mA, 82S129는 약 130 mA이므로 7805로 충분합니다.

### 2.2 소켓

ARIES 40핀 유니버설 ZIF 소켓 **하나**를 씁니다(`photo/20261121_124851.jpg`). 접점이 가로로 긴 홈이라 0.6인치 칩(2764)은 홈 바깥쪽 끝에, 0.3인치 칩(82S129, 82S123)은 가운데 칸막이를 사이에 두고 홈 안쪽 끝에 꽂힙니다.

납땜하지 않습니다. 보드 포트 헤더와 ZIF 다리를 점퍼선으로 직접 잇고, 칩 종류가 바뀔 때마다 그 칩의 결선표대로 점퍼를 다시 꽂은 뒤 그 칩용 펌웨어를 플래시합니다.

| 칩 종류 | 결선 | 점퍼 수 | 펌웨어 | 대상 |
| --- | --- | --- | --- | --- |
| 2764 | 2.3절 | 27 | `RomReader_2764.hex` | U45, U46, U65, U70 |
| 82S129 / 82S126 | 2.4절 | 16 + GND 1 + 콘덴서 2 | `RomReader_82S129.hex` | U50, U51, U36, U38, U18, U17 |
| 82S123 | 2.5절 | 16 + GND 1 + 콘덴서 2 | `RomReader_82S123.hex` | U5 |
| 2732, 2716 (24핀) | 2.3절 + 2.6절 | 27 + 브레드보드 1 | `RomReader_2764.hex` | 고도 F·KEY, Malum D0·E0·F0·KEY |

같은 종류끼리 묶어 읽으면 재배선과 플래시는 세 번이면 됩니다(2764·2732·2716 → 82S129 → 82S123). 같은 종류 안에서는 칩만 바꿔 꽂습니다.

규칙:

- ZIF에는 핀 번호가 인쇄돼 있지 않으므로 이 문서에서 번호를 정합니다. 레버가 위로 오게 놓았을 때 왼쪽 줄 맨 위가 ZIF 1번이고, 왼쪽 줄을 내려가 20번, 오른쪽 줄 맨 아래가 21번, 올라가 40번(오른쪽 줄 맨 위)입니다.
- 칩은 노치를 레버 쪽으로 향하게 하고, 칩 1번 핀을 ZIF 1번에 맞춰 위쪽으로 붙여 꽂습니다.
- 28핀: 칩 1–14번 → ZIF 1–14번, 칩 15–28번 → ZIF 27–40번(칩 핀 + 12). ZIF 15–26번은 비웁니다.
- 16핀: 칩 1–8번 → ZIF 1–8번, 칩 9–16번 → ZIF 33–40번(칩 핀 + 24). ZIF 9–32번은 비웁니다.
- 레버를 올린 상태에서 칩을 넣고 내립니다. 0.3인치 칩은 처음 한 번 `check`로 모든 데이터 비트가 움직이는지 확인합니다.
- 표에 없는 ZIF 핀에는 아무것도 꽂지 않습니다.

점퍼선: 보드 헤더는 수 핀이라 헤더 쪽은 암 단자를 씁니다. ZIF 다리에도 암 단자를 끼우는데, 다리가 가늘어 헐거우면 접촉이 끊길 수 있습니다. 접촉이 나쁘면 두 번 읽은 결과가 달라서 스크립트가 파일을 쓰지 않으니, 그때 해당 점퍼를 다시 꽂으면 됩니다. +5 V와 GND는 각 헤더의 9번, 10번을 씁니다(헤더마다 하나씩 있어 2764의 +5 V 세 가닥도 따로 뺄 수 있습니다).

ZIF 9–32번은 연결하지 않습니다. 주소 핀 순서가 차례대로가 아닙니다(5, 6, 7번이 A0, A1, A2).

/CE2(ZIF 38)는 GND(J121-10)에 고정해 항상 켜 두고, /CE1(ZIF 37)만 PC5(J121-6)로 켜고 끕니다. GND는 J117-10(ZIF 8)과 J121-10(ZIF 38) 두 곳에서 가져옵니다. 점퍼는 16가닥입니다(`HART/zif-wiring.html`, `HART/wiring_photo_82S129.jpg`와 같습니다).

**바이폴라 PROM(82S129, 82S123)은 아래 세 가지를 꼭 함께 답니다** (`photo/20261122_130057.jpg`, `photo/20261122_130123.jpg`):

| 추가 | 연결 | 비고 |
| --- | --- | --- |
| 세라믹 0.1 µF (`104`) | 브레드보드 **오른쪽 1번 줄(ZIF 40, 5 V)** ↔ **왼쪽 8번 줄(ZIF 8, GND)** 의 빈 구멍 | 방향 없음 |
| 전해 10 µF | 같은 두 줄. **긴 다리(+)를 오른쪽 1번 줄(5 V)**, 띠 쪽 짧은 다리(−)를 왼쪽 8번 줄 | 극성 주의 |
| GND 점퍼 1가닥 | **J104-10(GND)** → 브레드보드 **왼쪽 8번 줄**의 빈 구멍 | J104-9(5 V)와 헷갈리지 않게 |

82S123도 ZIF 40번이 VCC, ZIF 8번이 GND라 그대로 둡니다. 2764·24핀 결선으로 돌아갈 때는 이 셋을 뺍니다(2764에서는 ZIF 8번이 A2).

### 2.5 82S123 PROM (16핀, 32 × 8) 결선

| ZIF | 82S123 핀 | 신호 | 연결 | | ZIF | 82S123 핀 | 신호 | 연결 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | O1 | PF0 (J104-1) → D0 | | 40 | 16 | VCC | +5 V (J117-9) |
| 2 | 2 | O2 | PF1 (J104-2) → D1 | | 39 | 15 | /CE | PC5 (J121-6) |
| 3 | 3 | O3 | PF2 (J104-3) → D2 | | 38 | 14 | A4 | PB4 (J117-5) |
| 4 | 4 | O4 | PF3 (J104-4) → D3 | | 37 | 13 | A3 | PB3 (J117-4) |
| 5 | 5 | O5 | PF4 (J104-5) → D4 | | 36 | 12 | A2 | PB2 (J117-3) |
| 6 | 6 | O6 | PF5 (J104-6) → D5 | | 35 | 11 | A1 | PB1 (J117-2) |

| 8 | 8 | GND | GND (J117-10) | | 33 | 9 | O8 | PF7 (J104-8) → D7 |

**주의:** 칩 종류마다 핀 역할이 다릅니다. 특히 82S129와 82S123은 같은 16핀이지만 출력 핀 위치가 달라서, 다른 칩의 결선에 꽂으면 칩 출력과 MCU 주소 출력(PB)이 서로 맞붙어 칩이나 MCU가 상할 수 있습니다. 칩을 꽂기 전에 세 가지가 모두 같은 칩 종류인지 확인합니다: ① 점퍼 결선, ② 플래시한 펌웨어(부팅 메시지와 프롬프트에 칩 이름이 나옵니다), ③ 꽂을 칩. 덤프 스크립트도 펌웨어와 `-t`가 다르면 읽지 않고 멈춥니다.

82S129, 82S123 모두 O1을 D0(LSB)으로 둡니다. 비트 순서가 반대인 것으로 보이면 결선은 그대로 두고 파일에서 뒤집으면 됩니다.

### 2.6 2732, 2716 EPROM (24핀): 2764 결선 + 브레드보드 점퍼 1가닥

2764 결선(2.3절)과 2764 펌웨어를 그대로 씁니다. 바꾸는 것은 두 가지뿐입니다.

1. **브레드보드 점퍼 1가닥**: 오른쪽 열 **1번 줄(ZIF 40, 5 V)** 과 **3번 줄(ZIF 38)** 을 잇습니다(`24pin/20261122_042718.jpg`). 24핀 칩의 VCC(24번)가 ZIF 38에 옵니다. 2764의 26번(ZIF 38)은 NC라 이 점퍼를 꽂아 둔 채로 2764를 읽어도 됩니다.
2. **칩을 두 칸 내려 꽂기**: 노치는 레버 쪽, **칩 1번 = ZIF 3번**(브레드보드 3번 줄), 칩 끝이 14번 줄에 맞습니다. ZIF 1, 2, 39, 40번에는 칩 다리가 없습니다. **24핀 칩을 ZIF 1번부터 꽂지 않습니다.**

| 칩 | `-t` | 저장되는 내용 |
| --- | --- | --- |
| 2732 | `2732` | 8 KB로 읽어 앞뒤 4 KB가 같은지 확인하고 앞 4 KB 저장 |
| 2716 (MB8516 포함) | `2716` | 21번(VPP)이 A11 선(ZIF 35)에 걸리므로 A11이 High인 0x0800–0x0FFF 2 KB 저장(0x1800–0x1FFF와 같은지 확인) |

사진 결선도: `24pin/wiring_photo_2732.jpg`, `24pin/wiring_photo_2716.jpg`. 보드별 칩 위치: `GODO/zif-wiring.html`, `Malum/zif-wiring.html`.

### 2.7 시리얼과 ISP

FT232 TTL(5 V 점퍼)을 베이스보드 UART1 헤더에 연결합니다. 모듈의 3핀 RS-232 커넥터(MAX232, ±12 V)에는 연결하지 않습니다. FT232 VCC, DTR, CTS는 연결하지 않습니다.

| FT232 | 보드 UART1 |
| --- | --- |
| GND | 4 GND |
| RX | 2 TX1 (PD3) |
| TX | 3 RX1 (PD2) |

이 PC에서 FT232는 **COM11**, 통신은 **38400 8N1**, 흐름 제어 없음입니다. STK500은 보드 ISP 커넥터에 연결하며 **COM10**입니다.

### 2.8 전원과 USB 연결 (이 구성 그대로 씁니다)

| 항목 | 설정 |
| --- | --- |
| 보드 전원 | **12 V 1.5 A 어댑터**를 베이스 DC 잭에 꽂아 7805로 5 V를 만듭니다. 보드 전원은 이것 하나뿐입니다 |
| STK500 | 뒷면 **J3(3.3V/5V) 점퍼를 꽂지 않습니다.** 보드에 전원을 공급하지 않고 ISP 신호와 GND만 연결합니다. J3를 꽂지 않아도 플래시가 됩니다 |
| FT232 | 5V 점퍼, GND/RX/TX 세 가닥만 연결합니다. VCC는 연결하지 않습니다 |
| USB | STK500과 FT232를 **포트별 스위치가 있는 USB 허브**에 꽂아 씁니다 |
| ISP 경로 | STK500 10핀 → NewTC 변환 보드(AD-ISP-CVB) → 듀폰선 6가닥 → 모듈 J4. 색: 주황 VCC, 노랑 GND, 초록 RST, 파랑 SCK, 보라 MISO, 회색 MOSI. J4 1번(MOSI, 회색)이 5V INPUT(J6) 쪽입니다 |

5 V 어댑터는 쓰지 않습니다. DC 잭은 7805를 거치므로 9 V 이상이 필요합니다(매뉴얼 2.3절).

### 2.9 작업 가이드 (순서대로 따라 하기)

세 가지 펌웨어(2764, 82S129, 82S123) 모두(2732·2716은 2764 펌웨어) **플래시(펌웨어 교체)와 덤프(읽기)를 다른 연결 상태에서** 합니다. 아래 두 순서를 반드시 지킵니다.

> **1) 칩 종류를 바꿀 때: 플래시**
> - 켜는 순서: **STK500 on → FT232(FTDI) on → 12 V 전원 인가**, 그다음 플래시
> - ISP 케이블은 모듈 J4에 꽂고, ZIF는 비워 둡니다
>
> **2) 칩 읽기: 덤프**
> - **2.1) STK500이 ATmega128 보드와 연결돼 있으면 안 됩니다.** ISP 케이블을 **모듈 J4에서 뽑습니다** (STK500 off로는 해결 안 됨)
> - **2.2) FT232가 PC에 연결된 상태에서 12 V off → 12 V on**, 그다음 덤프합니다

#### 그 밖의 규칙

1. **USB 장치 먼저, 12 V는 마지막.**
2. **칩을 꽂거나 뺄 때는 12 V 어댑터를 뽑습니다.**
3. STK500을 켠 뒤 몇 초 기다렸다가 플래시합니다.

#### 상태별 연결

| 연결 | 플래시할 때 | 덤프할 때 |
| --- | --- | --- |
| ISP 듀폰 하우징 (모듈 J4) | **꽂음** | **뽑음** (STK500과 보드 연결 없음) |
| 허브 STK500 포트 (COM10) | 켬 | 상관없음 |
| FT232 (COM11) | 켬 | 켬 (PC에 연결) |
| 12 V 어댑터 | STK500·FT232 다음에 꽂음 | FT232 연결된 상태에서 off → on |
| ZIF | 비움 | 읽을 칩 (레버 내림) |
| ZIF 결선 | 새 칩 종류 결선 | 같음 |

#### A. 칩 종류를 바꿀 때 (결선 바꾸기와 플래시)

1. 12 V 어댑터를 뽑습니다. ZIF에서 칩을 뺍니다.
2. 이전 점퍼를 모두 뽑고, 새 칩 종류의 결선표(2.3–2.6절, `HART/zif-wiring.html`)대로 꽂습니다.
3. 12 V와 USB 장치를 모두 끈 상태에서, 멀티미터로 ZIF 40번이 +5 V 쪽, GND 핀(2764는 ZIF 14, 16핀은 ZIF 8)이 GND 쪽에 이어졌는지 확인합니다. 82S129·82S123은 바이패스 콘덴서 2개와 GND 점퍼(2.4절)도 꽂습니다.
4. **ISP 듀폰 하우징을 모듈 J4에 꽂습니다**(회색 MOSI가 5V INPUT 쪽).
5. **STK500 on**: 허브의 STK500 포트를 켜고, 장치 관리자에 `Prolific USB-to-Serial Comm Port (COM10)`이 보이는지 확인합니다.
6. **FT232 on**: `USB Serial Port (COM11)`이 보이는지 확인합니다.
7. **12 V 전원 인가**: DC 잭 옆 Power LED(빨강)를 확인합니다.
8. 시그니처를 읽어 `0x1e,0x97,0x2`가 나오는지 확인한 뒤 플래시합니다(3절).
9. 새 칩 이름이 나오는지 확인합니다.

```powershell
python -c "import serial,time; s=serial.Serial('COM11',38400,timeout=1); s.write(b'info\r'); time.sleep(0.5); print(s.read(200).decode())"
```

   `82S129 size=256 mask=0x0F`처럼 새 칩 이름이 나오면 정상입니다.

10. **12 V 어댑터를 뽑고, ISP 듀폰 하우징을 J4에서 뽑습니다.** B로 갑니다.

#### B. 칩 하나 읽기 (덤프)

1. **ISP 듀폰 하우징이 J4에서 빠져 있는지** 확인합니다. STK500 포트는 켜져 있든 꺼져 있든 상관없습니다.
2. 12 V 어댑터가 뽑혀 있는 상태에서 칩을 ZIF에 꽂고 레버를 내립니다.
   - 노치는 레버 쪽, 칩 1번 = ZIF 1번(왼쪽 줄 맨 위, 브레드보드 1번 줄)
   - 28핀은 위로 바짝(ZIF 15–26번이 빔), 16핀은 위로 바짝(ZIF 9–32번이 빔), 24핀(2732·2716)은 두 칸 내려 ZIF 3번부터(2.6절, ZIF 40 ↔ 38 점퍼)
   - 칩을 빼기 전에 원래 보드에서의 방향을 사진으로 남깁니다
3. **FT232가 PC에 연결돼 있는지**(COM11) 확인합니다.
4. **12 V off → 12 V on**: 어댑터를 꽂고 Power LED를 확인합니다.
5. 덤프합니다(4절). 끝에 `wrote ...` 줄(파일 크기와 SHA-1)이 나오면 성공입니다. 4.1절 결과 표에 파일과 SHA-1을 적습니다.
6. 12 V 어댑터를 뽑고 칩을 뺍니다. 같은 종류의 다음 칩은 B의 2번부터 반복합니다(FT232는 연결된 채로 둠).

#### C. 작업 끝

1. 12 V 어댑터를 뽑습니다.
2. ZIF에서 칩을 빼서 원래 보드 위치와 방향으로 돌려 놓습니다.
3. 허브의 FT232 포트, STK500 포트를 끕니다.

문제가 생기면 [`doc/troubleshooting.md`](doc/troubleshooting.md)에서 증상을 찾습니다(실제로 겪은 문제와 원인, 해결 방법).

## 3. 빌드와 플래시

칩 종류마다 펌웨어가 따로 있습니다. 칩 종류는 빌드할 때 정해지고, 실행 중에는 바꿀 수 없습니다.

```bash
export PATH=/ucrt64/bin:$PATH
cd RomReader
make all-chips          # 세 개 모두
make CHIP=2764          # 하나만: 2764, 82S129, 82S123
```

| 칩 | 산출물 |
| --- | --- |
| 2764 | `RomReader/build/2764/RomReader_2764.hex` |
| 82S129 / 82S126 | `RomReader/build/82S129/RomReader_82S129.hex` |
| 82S123 | `RomReader/build/82S123/RomReader_82S123.hex` |

플래시는 **ZIF에서 칩을 뺀 상태**에서 합니다. 이전 칩 종류의 펌웨어가 새 결선에 꽂힌 칩을 잘못 구동하지 않게 하기 위해서입니다. 아래는 2764 예이고, `$chip`만 바꿉니다. avrdude는 `ATmega128_FreeRTOS` 폴더에서 빌드한 것을 씁니다.

```powershell
$chip = "2764"
$avr = "D:\msys64\home\milds\ATmega128_FreeRTOS\avrdude\build-ucrt64\src"
$env:PATH = "D:\msys64\ucrt64\bin;" + $env:PATH
& "$avr\avrdude.exe" -C "$avr\avrdude.conf" -c stk500v2 -P COM10 -b 115200 -p m128 -U "flash:w:RomReader\build\$chip\RomReader_$chip.hex:i"
```

퓨즈는 바꾸지 않습니다. JTAG는 펌웨어가 런타임에 끕니다.

플래시 전에 시그니처를 읽어 연결을 확인할 수 있습니다(쓰기 없음). 정상이면 `0x1e,0x97,0x2`입니다. 퓨즈는 lfuse `0xEF`, hfuse `0xD9`, efuse `0xFF`로 읽힙니다.

```powershell
& "$avr\avrdude.exe" -C "$avr\avrdude.conf" -c stk500v2 -P COM10 -b 115200 -p m128 -U signature:r:-:h
```

## 4. 덤프 절차

칩 종류를 바꿀 때(처음 포함): **2.9절 A**대로 결선을 바꾸고, **STK500 on → FT232 on → 12 V 인가** 순으로 켠 뒤 ZIF가 빈 상태에서 그 칩용 펌웨어를 플래시합니다(3절). 프롬프트(`[82S129]> ` 등)가 새 칩 이름인지 확인한 뒤 12 V를 뽑고 **ISP를 J4에서 뽑습니다.**

칩마다 (**2.9절 B**):

1. **ISP 케이블이 J4에서 빠져 있어야 합니다** (STK500과 보드 연결 없음. STK500 off로는 안 됨).
2. 12 V 어댑터를 뽑은 상태에서 칩을 ZIF에 꽂고 레버를 닫습니다. 노치 방향을 확인하고, 칩을 빼기 전에 원래 보드에서의 방향을 사진으로 남깁니다.
3. **FT232가 PC에 연결된 상태에서 12 V off → 12 V on.** 베이스보드 PG0 LED(D101)는 명령 처리 중에 켜지고, PG1 LED(D102)는 마지막 `dump`에서 불안정한 주소가 있었을 때 켜집니다.
4. 덤프합니다. `-t`는 플래시한 펌웨어와 같아야 하며, 다르면 스크립트가 읽지 않고 멈춥니다. 기본으로 두 번 읽어 비교하고, 각 주소도 펌웨어가 세 번씩 읽습니다. 하나라도 다르면 파일을 쓰지 않습니다. 82S129·82S123 같은 바이폴라 칩은 `-n 15 --vote`로 여러 번 읽어 다수결로 저장하고, 엇갈린 주소는 `.marginal.txt`에 남길 수 있습니다.

```powershell
python tools\romdump.py -p COM11 -t 2764 -o rom\HART\U45_CD8.bin
```

```powershell
python tools\romdump.py -p COM11 -t 2732 -o rom\Malum\D0.bin
```

```powershell
python tools\romdump.py -p COM11 -t 2716 -o rom\Malum\KEY.bin
```

```powershell
python tools\romdump.py -p COM11 -t 129 -o rom\HART\U50_1.bin -n 15 --vote
```

```powershell
python tools\romdump.py -p COM11 -t 123 -o rom\HART\U5_82S123.bin -n 15 --vote
```

스크립트는 먼저 `check`를 실행해 칩이 응답하는지 보여 주고, 끝에 크기와 SHA-1을 출력합니다. 이 값을 HART 목록 문서의 결과 표에 옮기면 됩니다. pyserial이 필요합니다(`pip install pyserial`).

5. 12 V 어댑터를 뽑은 뒤 칩을 빼서 원래 위치와 방향으로 되돌립니다.

8 KB 2764 한 번 읽는 데 약 6초 걸립니다(두 번 읽어 약 15초).

### 터미널 명령

시리얼 터미널(COM11, 38400 8N1)로 직접 써도 됩니다. 프롬프트는 `[2764]> `처럼 플래시된 펌웨어의 칩 이름을 보여 줍니다. 숫자 인자는 16진수입니다. 펌웨어는 빈 줄(Enter만)을 받으면 프롬프트를 다시 출력하지 않습니다. 터미널에서 응답을 확인할 때는 `info`처럼 명령을 입력합니다.

| 명령 | 설명 |
| --- | --- |
| `info` | 펌웨어의 칩 종류, 크기, 데이터 마스크 |
| `check` | /CE를 끈 상태와 켠 상태를 비교. 칩이 없거나 전원, 데이터선 문제를 알려 줍니다 |
| `hex [addr] [len]` | 16진 보기. 기본 0번지부터 0x100바이트. 불안정한 바이트 뒤에는 `?` |
| `peek <addr>` | 한 주소 읽기 |
| `dump` | 칩 전체를 Intel HEX로 출력. `#`로 시작하는 줄은 상태 |
| `help` | 명령 목록 |

`check` 해석:

- `disabled: bits pulled low` 가 0이 아니면 칩이 꺼져 있어도 데이터선을 끌어내리는 것입니다. /CE 결선이나 쇼트를 확인합니다.
- `WARN no bit ever driven low` 는 칩이 없거나, 전원이 없거나, /CE가 연결되지 않은 경우입니다.
- `NOTE some data bits never 0` 는 해당 비트의 데이터선이 빠졌을 가능성이 큽니다(데이터가 실제로 그럴 수도 있습니다).

## 5. STK500 드라이버

STK500 USB-시리얼(Prolific) 드라이버는 `driver/STK500-COM-Driver.zip`에 있습니다. 장치 관리자에 STK500이 없거나 노란 느낌표가 있으면 이 압축을 풀어 설치합니다. 설치 후 포트 번호(이 PC는 COM10)를 확인하고 avrdude 명령의 `-P`에 맞춥니다. 이 PC에는 이미 설치돼 있습니다(Prolific 3.3.2.105).

FT232는 별도입니다. FTDI 드라이버가 잡히면 "USB Serial Port"로 보이며, 이 PC에서는 COM11입니다.

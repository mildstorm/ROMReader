# 문제 해결 기록

README는 **성공한 방식만** 담습니다. 이 문서는 2026-11-21~22에 실제로 겪은 문제와 원인, 해결 방법을 모아 둔 참고 자료입니다. 증상이 나오면 여기서 찾고, 따라 할 순서는 README 2.9절을 봅니다.

## 1. 연결과 전원 (STK500, FT232, USB)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 장치 관리자에 STK500이나 FT232가 `알 수 없는 USB 장치(장치 설명자 요청 실패)`로 나오고 COM 포트가 없음 | 12 V가 먼저 들어가 보드 전압이 ISP 선(STK500)이나 UART TX 선(FT232)으로 새어 들어가 USB 장치가 반쯤 켜진 상태. 허브 포트 상태가 나쁠 때도 생김. 드라이버 문제는 아님 | 12 V를 뽑고 → 그 허브 포트를 껐다 켜고 → COM 포트가 잡히면 12 V를 꽂음. 반복되면 그 장치만 PC 본체 포트에 직접 꽂아 확인 |
| `cannot open port COM10` | USB 포트를 바꾸면 COM 번호가 바뀜(COM13, COM14, COM15 …) | 장치 관리자의 Prolific 포트 번호로 avrdude `-P`를 바꿈 |
| avrdude `timeout communicating with programmer` | STK500을 막 켰거나, 12 V가 먼저 들어가 STK500 프로그래머 칩이 멈춤 | 몇 초 기다렸다 다시 시도. 안 되면 12 V 뽑기 → STK500 포트 껐다 켜기 → FT232 → 12 V 순으로 다시 켬 |
| avrdude `initialization failed`, 시그니처 `00 00 00`·`1E FF 02`, 퓨즈가 모두 `0xFF` | ISP 듀폰선 접촉 불량(변환 보드 쪽 또는 모듈 J4 쪽). ISP 클럭(`-B`)을 낮춰도 안 고쳐짐 | 양쪽 듀폰 하우징을 빼서 끝까지 눌러 다시 꽂음. 시그니처가 여러 번 `1E 97 02`로 나온 뒤 플래시 |
| avrdude가 `Vtarget : 0.0 V` | 보드에 12 V가 안 들어감(STK500 J3는 열어 두므로 STK500이 전원을 주지 않음) | 12 V 어댑터와 Power LED 확인 |
| STK500 J3 점퍼를 5V로 꽂아 봄 | STK500이 USB 5 V를 보드로 내보내 12 V 전원과 맞물림. 필요 없음 | J3는 꽂지 않음(README 2.8절). J3 없이 플래시됨 |
| FT232가 COM11로 잡히는데 보드 응답이 전혀 없음(속도를 바꿔도 0바이트) | FT232 TTL 쪽 고장. 루프백(FT232 TX ↔ RX를 잇고 글자 보내기)으로 확인하니 글자가 돌아오지 않음 | FT232 교체(두 번째 FT232로 해결, COM11 그대로). 교체 전 5V/3.3V 점퍼 캡도 확인 |
| 멀티미터 도통 시험에서 5 V ↔ GND가 계속 삐 소리 | 12 V는 뽑았지만 STK500·FT232가 켜져 있어 그쪽 전압이 측정을 방해 | 12 V와 USB 장치를 모두 끈 뒤 다시 잼(콘덴서 충전 때문에 짧게 삐 소리 나는 것은 정상) |

## 2. 보드가 응답하지 않음 (덤프 전)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 터미널에 `ATmega128 ROM ?`가 끊긴 채 계속 반복 | ISP 케이블이 J4에 꽂혀 있고 STK500이 꺼져 있음 → 꺼진 STK500이 RESET을 끌어내림 | 덤프할 때는 ISP를 J4에서 뽑음 |
| RESET을 눌러도 보드 무응답, 칩을 빼면 정상 | 위와 같은 상태(STK500이 RESET이나 SCK를 붙잡음). 칩 고장으로 오해하기 쉬움 | ISP를 J4에서 뽑고 12 V off → on |
| `romdump.py`가 `no prompt from board ... b''`, 터미널에서는 `info`가 응답 | 예전 스크립트가 빈 줄(Enter)만 보내고 프롬프트를 기다림. 펌웨어는 빈 줄에 프롬프트를 다시 출력하지 않음 | 수정됨(스크립트가 `info`로 시작). 터미널에서도 `info`처럼 명령을 입력해 확인 |
| `check`가 `WARN no bit ever driven low`, 덤프가 모두 0xF | ZIF 레버가 올라가 있음(칩이 접촉 안 됨) | 레버를 내림. 스크립트는 모든 값이 같으면 저장하지 않음 |

## 3. 바이폴라 PROM (82S129, 82S123)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 덤프 도중 HEX에 깨진 문자가 섞이고 보드가 멈춤(`check`는 통과) | 바이폴라 칩이 켜져 있는 동안 전류가 크게 튀어 긴 점퍼선의 전원·GND가 출렁임 | 바이패스 0.1 µF + 10 µF, J104-10 → ZIF 8 GND 점퍼(README 2.4절). 펌웨어는 읽는 동안만 칩을 켜도록 수정됨 |
| 82S129에서 A1=1 주소(0x02, 0x03, 0x06 …)가 틀리게 읽힘. 대부분 0이거나 바로 앞 주소 값 | ① 예전 펌웨어가 주소를 바꾸고 2 µs 만에 읽어 칩 출력이 아직 바뀌지 않음 ② ISP 케이블이 J4에 꽂혀 SCK(= PB1 = A1)에 부하가 걸림(STK500이 켜져 있어도 생김) | ① 펌웨어 수정됨(한 번 버리고 20 µs 뒤 읽음) ② 덤프할 때 ISP를 뽑음. 예: U51은 ISP를 꽂고 읽었을 때 0x0E, 0x16, 0x1A가 4로 잘못 읽혀 다시 읽음 |
| 같은 주소 한 곳만 가끔 UNSTABLE(예: U38 0xF7 비트 0) | 그 출력 비트의 High 전압이 판정 경계에 걸림. 칩을 꺼도 O1이 약하게 Low로 끌리는 칩(U50, U51, U38)에서 보임 | `-n 15 --vote`로 여러 번 읽어 다수결 저장. 보고값이 15회 모두 같으면 그 값 사용 |
| 칩을 꽂으면 보드가 리셋을 반복하거나 멈추고, 칩을 빼면 정상 | 대부분 ISP·STK500 상태 문제였음(위 2절). U50을 고장으로 의심했으나 전원 핀 저항이 정상 칩과 같았고, ISP를 뺀 뒤 정상으로 읽힘 | ISP를 뽑고 다시 시도. 칩을 의심하기 전에 같은 종류의 다른 칩으로 비교 |
| 16핀 칩을 거꾸로 꽂음 | 전원이 반대로 걸림(칩 8번에 5 V, 16번에 GND). 보드 전압이 떨어져 MCU가 멈춤 | 즉시 12 V를 뽑음. U36은 1–2분 거꾸로 꽂혔으나 뜨겁지 않았고 이후 정상으로 읽힘·HART 정상 부팅. 이후 STK500으로 시그니처·플래시 대조로 MCU 정상 확인 |
| 결선을 바꾼 뒤 칩을 꽂기 전에 단락이 의심됨 | 24핀용 브레드보드 점퍼(ZIF 40 ↔ 38)를 82S129 결선에 남기면 ZIF 40(5 V)과 ZIF 38(/CE2 = GND)이 맞붙음 | 82S129·82S123으로 바꿀 때 ZIF 40 ↔ 38 점퍼를 반드시 뺌 |

## 4. 24핀 EPROM (2732, 2716)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 덤프가 이상하거나 칩이 뜨거움 | 24핀 칩을 ZIF 1번부터 꽂음(전원 핀이 어긋남) | 두 칸 내려 칩 1번 = ZIF 3번, ZIF 40 ↔ 38 브레드보드 점퍼 |
| 2764 덤프에서 16바이트마다 같은 값이 두 번씩 반복(예: 0x1B00 줄 = 0x1B10 줄) + 같은 주소 몇 곳 UNSTABLE | 주소선 A4 점퍼(J117-5 ↔ ZIF 6) 또는 칩 6번 다리 접촉 불량 | 해당 점퍼와 칩을 다시 꽂음(GODO E에서 겪음). 덤프 파일에서 `d[a] == d[a ^ (1<<b)]` 비율로 주소선 고정 여부를 확인할 수 있음 |
| 칩 표기를 읽을 수 없음(GODO F) | 표면이 닳음 | 2732로 읽어 앞뒤 4 KB가 같으면 2732(`-t 2732`가 자동 확인). TI TMS2532는 핀 배치가 달라 이 방식으로 안 읽힘 |

## 5. 칩 정체 확인

| 상황 | 방법 |
| --- | --- |
| 표기가 안 보이는 칩(U17) | 비스듬한 조명에서 다시 찍음 → `N82S129N K8509`로 읽힘. 보드에서 8번 ↔ 6502 1번(GND), 16번 ↔ 6502 8번(VCC), 13·14번 묶음 등 도통으로 핀 배치를 확인한 뒤 읽음 |
| PROM인지 로직 칩인지 모름 | 리더에 꽂기 전에 전원 핀(8번 GND, 16번 VCC)과 /CE 핀 배치를 보드에서 도통으로 확인. 로직 칩을 PROM 결선에 꽂으면 출력끼리 맞붙을 수 있음 |

| 증상 | 원인 | 해결 |

| 칩을 다시 꽂은 뒤 사각 격자 화면 | 칩 문제 아님. 전원 스위치를 천천히 켜면 사각 격자, 빨리 켜면 로고 | 스위치를 한 번에 켜거나 Ctrl+RESET. 원인 추적은 HART [`docs/09-verified-baseline.md`](https://github.com/mildstorm/HART/blob/main/docs/09-verified-baseline.md) 6-4절 |
